## Activation Contract

Load on handoff from `spec-design-plan`, or directly when DESIGN.md is missing, a frontend project starts with no UI, or DESIGN.md does not represent the shipped UI. Applies to any stack.

## Hard Rules

- Load `../_shared/spec-design/rules.md` first; its rules apply here.
- The only deliverable is a DESIGN.md that matches the real UI, plus literals unified to it. Build no features here.
- Run the Liveness check before any add-or-retire decision and the Role check before any merge or replacement.
- Replace literals automatically only at ΔE < 2 and the same role; ask the user at ΔE ≥ 10 or on a role mismatch.
- Edit an existing DESIGN.md; never replace it wholesale without asking.
- Consumers are generated by `spec-design-apply`; hand off for Generate instead of hand-writing token files.

## Decision Gates

| Project state | Mode |
|---|---|
| UI code exists, no DESIGN.md | Extract |
| No UI code yet | Seed |
| DESIGN.md exists but does not match the UI | Reconcile |
| DESIGN.md already trusted | Nothing to do; hand back to the caller |

## Execution Steps

1. Detect the mode. If UI code exists, run the Audit from `../_shared/spec-design/checks.md` (read-only).
2. Run that mode's workflow from `references/workflows.md`.
3. Lint DESIGN.md.
4. Hand off to `spec-design-apply` for Generate, then run Unify.
5. Offer to add a pointer to DESIGN.md in the project's AGENTS.md or CLAUDE.md so every agent reads it before UI work.
6. Hand back to the caller once DESIGN.md is trusted.

## Output Contract

Return: mode, audit summary (counts per ΔE band, translucent and named colors, foreign palettes, duplicated sources), liveness findings, files created or changed, lint result, and open decisions for the user.
